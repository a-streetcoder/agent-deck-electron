# SBX-01 spike: srt and Zerobox inside the server image (2026-10-17)

Ticket ade-pv1c, ADR 0007. Run on the VM (`dev`: Debian 13, kernel 6.12.111, Docker 26.1.5,
AppArmor parser 4.1.0) from a fresh clone of `poc/shared-server` in `~/sbx-spike`, image tag
`agent-deck-server:sbx`, scratch volume `sbx-data`. The production stack was not touched.

**Recommendation: the container with the two profiles plus `systempaths=unconfined`.** srt runs
fully sandboxed inside it (no `enableWeakerNestedSandbox`, no `allowNestedUserNamespaces`), every
check passes, and the overhead is about 0.2 s per wrap and nothing measurable inside the sandbox.
The host-unit fallback is not needed.

## Versions

| Component                       | Version                                                                                                  |
| ------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `@anthropic-ai/sandbox-runtime` | 0.0.80 (global npm install in the image, root-owned, mode 755)                                           |
| Zerobox                         | 0.3.3 (`npm i -g --prefix /data/home/.npm-global` as uid 1000; installs fine in the read-only container) |
| bubblewrap                      | 0.8.0 (Debian bookworm, the runtime base)                                                                |
| socat / ripgrep                 | 1.7.4.4 / 13.0.0                                                                                         |
| Docker profiles derived from    | moby v26.1.5 `profiles/seccomp/default.json` and `profiles/apparmor/template.go`                         |

srt's `apply-seccomp` helper ships inside the package (`vendor/seccomp/x64/apply-seccomp`, 755),
so it is readable and executable by uid 1000. `curl` was added to the image as well: the slim
base has none, the checks need it, and sessions will.

## What blocked user namespaces, and the fixes

1. **AppArmor**: docker-default refuses `userns_create` (audit:
   `apparmor="DENIED" operation="userns_create" profile="docker-default"`). docker-default also
   has `deny mount`. `deploy/apparmor-agent-deck` (profile `agent-deck-sandbox`) is docker-default
   plus `userns, mount, remount, pivot_root,`.
2. **seccomp**: Docker's default allows `unshare`, `setns`, `mount`, `umount2`, `sethostname`,
   `setdomainname` and namespace flags on `clone` only with `CAP_SYS_ADMIN`, has no `pivot_root`,
   and answers `clone3` with `ENOSYS`. `deploy/seccomp.json` is the default minus the three
   capability-less clone/clone3 rules, plus one unconditional allow for `clone, clone3, unshare,
setns, mount, umount, umount2, pivot_root, sethostname, setdomainname`. Nothing else was
   refused (no seccomp or AppArmor audit records in the passing runs).
3. **Masked /proc** (not a profile): with both profiles `unshare -Ur` works, but bwrap fails with
   `bwrap: Can't mount proc on /newroot/proc: Operation not permitted`. No LSM record: the kernel
   refuses a new procfs in a user namespace while the container's /proc has overmounts
   (Docker masks `/proc/kcore`, `keys`, `timer_list`, `acpi`, `asound` and makes `bus`, `fs`,
   `irq`, `sys`, `sysrq-trigger` read-only). `--security-opt systempaths=unconfined` removes the
   masks and srt then works. To keep what the masks gave, the AppArmor profile adds
   `deny @{PROC}/{keys,timer_list,sched_debug,timer_stats,latency_stats} rwklx`,
   `deny @{PROC}/{acpi,asound,scsi}/** rwklx` and `deny @{PROC}/{bus,fs,irq}/** wklx`; docker-default's
   own denies already cover `kcore`, `sysrq-trigger` and `/proc/sys` writes. Measured: `cat
/proc/keys` and `/proc/timer_list` are refused in the container and in the sandbox, and writing
   `/proc/sysrq-trigger` is refused in the sandbox.

Load the AppArmor profile on the host once (it is additive; docker-default is unchanged):

```sh
sudo apparmor_parser -r -W deploy/apparmor-agent-deck
```

## Exact docker run flags

```sh
docker run --rm --name sbx-check --user 1000:1000 --cap-drop ALL \
  --security-opt no-new-privileges:true \
  --security-opt seccomp="$PWD/deploy/seccomp.json" \
  --security-opt apparmor=agent-deck-sandbox \
  --security-opt systempaths=unconfined \
  --read-only --tmpfs /tmp:exec,size=1g \
  -v sbx-data:/data --memory 2g --cpus 2 \
  --entrypoint bash agent-deck-server:sbx /sbx/<script>
```

Compose equivalent for SBX-04: `security_opt: [no-new-privileges:true, seccomp=./seccomp.json,
apparmor=agent-deck-sandbox, systempaths=unconfined]` with the existing `cap_drop: [ALL]`,
`read_only: true` and `/tmp` tmpfs. The server image still starts and answers `/health` with
these flags. Image size 584 MB unpacked (566 MB before).

## Checks

srt settings: no-network file `{"network":{"allowedDomains":[],"deniedDomains":[]},
"filesystem":{"denyRead":["/data/secret"],"allowWrite":["/data/work"],"denyWrite":[]}}`; the
GitHub file is the same with `allowedDomains: ["github.com","*.github.com"]` and `/tmp` writable.
Zerobox: `zerobox --strict-sandbox --allow-read=/data --allow-write=/data/work
--deny-read=/data/secret [--allow-net=github.com,*.github.com] -- <cmd>`.

| Check                                           | srt 0.0.80                                    | Zerobox 0.3.3                                                            |
| ----------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------ |
| a. `unshare -Ur id -u` in the container         | pass (0)                                      | same container                                                           |
| b. write `/data/work`                           | pass                                          | pass                                                                     |
| b. write `/data/other` refused                  | pass (`Read-only file system`)                | pass (`Read-only file system`)                                           |
| b. read `/data/other`                           | pass                                          | pass, only with `--allow-read=/data` (its default profile hides `/data`) |
| b. `curl https://github.com` with no network    | pass (refused: proxy 403)                     | pass (refused: `Could not resolve host`)                                 |
| c. `curl https://github.com` allowed, via proxy | pass (200)                                    | pass (200)                                                               |
| c. `curl https://example.com` refused           | pass (403 `host is not on the allow list`)    | pass (403)                                                               |
| c. direct connection bypassing the proxy        | refused (`--noproxy '*'`: no DNS, own net ns) | refused                                                                  |
| d. `denyRead /data/secret` hides the file       | pass (directory empty, `No such file`)        | pass (`Permission denied`)                                               |
| e. `git clone --depth 1` octocat/Hello-World    | pass                                          | pass                                                                     |
| nested `unshare -Ur` inside the sandbox         | refused (EPERM, srt's seccomp layer)          | **allowed** (returns 0)                                                  |
| works without `systempaths=unconfined`          | no (bwrap cannot mount /proc)                 | runs, but the sandbox gets an empty /proc                                |
| `/proc/keys` inside the sandbox                 | refused                                       | refused                                                                  |

Namespaces inside srt: new user, mount, pid and net namespaces, `CapEff` 0, `NoNewPrivs` 1, three
seccomp filters (Docker's, srt's two). Zerobox: same namespaces, two filters.

f. Config srt needed: none beyond the settings above. Not needed: `allowNestedUserNamespaces`,
`bwrapPath`, `socatPath`, `seccomp.applyPath` (bwrap and socat are on PATH, the helper is
packaged). Requirements the provider (SBX-02) must meet:

- The settings file must be complete: srt refuses a file without `network.deniedDomains`
  (`does not hold a valid config — network.deniedDomains: Required`) rather than fall back.
- `/tmp/claude` must exist before the wrap: srt sets `TMPDIR=/tmp/claude` and makes it writable,
  but does not create it (`mktemp: failed to create directory via template '/tmp/claude/tmp.XXXXXXXXXX'`).
- Node's `fetch` ignores `HTTPS_PROXY`: corepack failed with `getaddrinfo EAI_AGAIN
registry.npmjs.org` until `NODE_USE_ENV_PROXY=1` was set (Node 22.23 supports it). Pi is a Node
  process; its model-provider calls need the same unless it uses its own proxy agent.

Messages srt printed (`--debug`):

- `apply-seccomp: could not set user.max_user_namespaces (Permission denied); the seccomp filter alone keeps the command from making namespaces`
  (on every run; the AppArmor `deny @{PROC}/sys/[^k]** w` rule from docker-default refuses the
  write; the seccomp layer still refuses nested namespaces, as measured above).
- `No placeholder for non-existent deny path /app/.bash_profile: it is read-only there` (and the
  other mandatory deny paths, relative to the working directory).
- Network refusal: `No matching rule, denying: example.com:443`, `Connection blocked to
example.com:443`, response `403 host is not on the allow list`, header `X-Proxy-Error: blocked-by-allowlist`.
- Write refusal: only the command's own `Read-only file system`; srt logs no violation for it on Linux.

Zerobox `--debug` prints a structured proxy decision
(`network.policy.decision="deny" ... server.address="example.com"`, `CONNECT blocked ... reason=not_allowed`).
Its default environment drops everything but PATH, HOME, USER, SHELL, TERM, LANG, and its
sandbox denies reading `/data/home/.bashrc`.

## Three-stack smoke (srt, uid 1000, HOME=/data/home)

allowWrite `["/data/work","/data/home"]`; allowedDomains: `github.com`, `*.github.com`,
`*.githubusercontent.com`, `registry.npmjs.org`, `*.npmjs.org`, `repo.yarnpkg.com`, `pypi.org`,
`files.pythonhosted.org`, `astral.sh`, `*.astral.sh`, `sh.rustup.rs`, `static.rust-lang.org`,
`crates.io`, `index.crates.io`, `static.crates.io`. Projects created inside the sandbox.

| Stack                                                                                                                                         | Result | Cold (empty volume) | Warm  | First failing command                          |
| --------------------------------------------------------------------------------------------------------------------------------------------- | ------ | ------------------- | ----- | ---------------------------------------------- |
| pnpm: `corepack pnpm install` (pnpm 10.18.3, lodash) + `pnpm test` (node --test)                                                              | pass   | 1.6 s               | 0.9 s | none (needs `NODE_USE_ENV_PROXY=1`, see above) |
| uv: install script into `~/.local/bin` (uv 0.13.1), `uv init --lib`, `uv add --dev pytest`, `uv sync`, `uv run pytest` (managed CPython 3.15) | pass   | 3.6 s               | 0.6 s | none                                           |
| Rust: `rustup` minimal into the home (cargo 1.99.1), `cargo new`, `cargo build`                                                               | fail   | 9.4 s               | 0.4 s | `cargo build`: `linker 'cc' not found`         |

The Rust failure is the image, not the sandbox: the same `cargo build` fails outside the sandbox
too. The runtime image has no C toolchain; that is ADR 0007's builder layer (SBX-04). rustup
itself (download, install, 593 MB in `~/.rustup`) works inside the sandbox.

## Overhead (same container, medians of 3, ms)

Work timed inside the sandboxed shell; start cost timed outside over 10 wraps of `true`.

| Measure                           | none | srt  | Zerobox |
| --------------------------------- | ---- | ---- | ------- |
| spawn `/bin/true` 200 times       | 67   | 68   | 66      |
| read 1000 small files (`cat`)     | 9    | 8    | 9       |
| `git clone --depth 1` Hello-World | 460  | 513  | 511     |
| 10 wraps of `true` (start cost)   | 9    | 2030 | 1300    |

Inside the sandbox nothing is measurable but the proxy hop on network (about 50 ms on a clone).
Each wrap costs about 200 ms with srt and 130 ms with Zerobox; ADR 0007 wraps once per Pi
process, so this is a per-session start cost.

## Recommendation and evidence

Container with profiles. srt passes every fence check inside the hardened container (non-root,
`cap_drop ALL`, read-only root, `no-new-privileges`) once the container has
`deploy/seccomp.json`, `apparmor=agent-deck-sandbox` and `systempaths=unconfined`; the masks
lost by the last flag are restored by AppArmor rules. Keep srt as ADR 0007 decided: it refuses
nested user namespaces (Zerobox 0.3.3 does not, so a command inside Zerobox can build a mount
tree of its own), and it fails closed when /proc cannot be mounted where Zerobox runs on with an
empty one. Zerobox is faster to start (130 versus 200 ms) and installs as uid 1000 into the
volume, so it stays a viable drop-in.

Not tried: the host path (step 6 of the dispatch), because the container path works; Pi under
srt (SBX-02); `credentials`/`tlsTerminate` (SBX-05).
