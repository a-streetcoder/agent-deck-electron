# Native functional parity audit — 2026-07-24

## Baseline and method

This report compares:

- **Native macOS:** clean commit `6ba89a5` in `/Users/andrea/Documents/GitHub/agent-deck`.
- **Electron:** exact committed baseline `e2b64fa` in `/Users/andrea/Documents/GitHub/agent-deck-electron`, including the LOOP-27 implementation from commit `57f7974` and the committed validation support.

Those comparison commits remain the fixed original audit baseline. Later implementations, closures, and validation cited below are post-baseline corrections to this living register; they do not move or redefine that baseline.

The scope is functionality, logic, persistence, safety, runtime behavior, and portable product outcomes. Styling, layout, animation, and pixel polish are excluded. Persisted identity/profile asset management is included; visual rendering and style parity are not. Native source is the product reference, not automatically the required implementation architecture.

The original audit traced source, persistence, launch, runtime, cancellation, failure, watcher, Electron main/preload, packaging, and nearby test paths. Tests were inspected but **not generally executed for the original audit**, so most source-backed “present” findings are not fresh runtime certifications. LOOP-27 was subsequently validated on macOS arm64 with focused real-Pi isolated-worktree coverage; browser review, reload, and merge-suppression coverage; Electron opaque-ID reveal coverage; and relevant unit and safety tests. SKL-22 was subsequently validated with native managed-repository security, server, real-Pi, renderer/backend, and packaged Electron containment coverage across Linux, Windows, and macOS; Windows failures after those checks were unrelated Loop tests. The full E2E suite was also run but had unrelated existing failures, so this report does not claim that suite passed.

Evidence marked **E** is in `agent-deck-electron`. Evidence marked **N** is in native `agent-deck`. Paths are kept short in the register so each difference remains scannable.

## Status and priority taxonomy

| Term           | Meaning                                                                                       |
| -------------- | --------------------------------------------------------------------------------------------- |
| **Present**    | Electron has the corresponding functional behavior.                                           |
| **Missing**    | Electron has no corresponding user behavior.                                                  |
| **Partial**    | A useful path exists, but a distinct behavior, state, or persistence path is absent.          |
| **Divergent**  | Both apps implement the area, but users get materially different behavior.                    |
| **Unsafe**     | The Electron path can violate a write, data, isolation, or release boundary.                  |
| **Unverified** | Source does not establish safe parity; focused validation is still required.                  |
| **Decision**   | Product/privacy policy must decide whether this should be ported.                             |
| **Equivalent** | The implementation differs, but the portable outcome is materially the same. It is not a gap. |

| Priority | Meaning                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------ |
| **P0**   | Release/parity blocker. No currently registered gap remains at this priority.                    |
| **P1**   | Data-loss/write-boundary risk, isolation/release safety issue, or missing load-bearing workflow. |
| **P2**   | Material limitation with a narrower usable path or workaround.                                   |
| **P3**   | Lower-frequency depth, convenience, diagnostics, or a product decision.                          |

## Executive verdict

Electron has a real and broad cross-platform product. Core Pi sessions stream incrementally. Resource CRUD, provider login, worktrees, Git, memory, MCP, issue browsing, terminal, browser, preview, files, diffs, onboarding, notifications, and signed/notarized macOS packaging all have working source paths.

It is **not at full native functional parity**.

- **No remaining P0 Loop structure gap:** Maker+Checker, Agent Pipeline, report-only Parallel Agents, Discovery/Triage, and terminal Human Approval checkpoints now have native-flat authoring and dedicated orchestration. Human Approval records and resolves durable app-data checkpoints without allocating Pi, validation, checkout-lock, or worktree resources.
- **P1 safety posture:** legacy copied-skill updates now three-way merge the complete payload tree and require per-path choices for overlapping changes; there is no coarse whole-folder remote action. Their durable transaction/recovery path, resource catalog mutations, managed `collection-v1` repositories and snapshots, requested project-session worktree isolation, and release synchronization fail closed when their safety boundary cannot be established.
- **P1 workflow gaps:** transcript attachment fidelity is incomplete; per-message fork/rerun is absent; and durable general child records are absent. Loop run timelines, proven launch ownership, and validated retained-worktree review are present; apply/discard decisions are implemented and covered by focused server/E2E tests. Running-turn guidance/follow-up input is present; arbitrary crash-orphan process discovery remains unavailable.
- **Distribution is only partly cross-platform:** the macOS DMG and bundled Pi are real. App updates, independent Pi updates, and Windows/Linux release/sign/update pipelines remain absent.

The honest release sequence is: close the remaining data and release hazards, extend durable orchestration/session records, then complete portable update and catalog depth.

## Corrections to older parity claims

- Provider login is not OAuth-only. API-key and OAuth login, search, grouping, method choice, browser launch, re-authentication, and credential replacement are present. Only an explicit renderer logout/remove action is missing.
- macOS packaging is not parked. Electron has an electron-builder DMG path with hardened runtime, signing, notarization, and bundled pinned Pi.
- Notifications and badges are present. Their remaining gaps are all-session observation, distinct-session counting, durable state, and click routing.
- Basic named, parallel, and streaming subagents work. The missing area is the richer parent tool catalog and durable/continuable child model.
- MCP HTTP, OAuth backend, live tools, and agent allowlists work. HTTP creation/edit, automatic callback, assignments, provenance, and advanced config remain incomplete.
- Packaged Electron normally needs no manual Pi installation. Doctor install/update/repair gaps mainly affect development, external runtimes, and independent runtime maintenance.
- Whole-session duplicate is present. It is not equivalent to native per-message Pi fork/rerun.
- Loop worktree isolation and retained-worktree review retain the focused-runtime validation recorded for LOOP-27. Apply/Discard was implemented later and is covered by focused server/E2E tests; it is not assigned that same certification here. General Git review remains read-only, while the dedicated Loop path applies only the exact reviewed patch after source-checkout preflights or implements Discard by atomically archiving the proven worktree under Agent Deck's private root while retaining the branch and artifacts.
- **Project-local authored skills, agents, and prompts ARE a native feature — the "intentionally unsupported on both sides / not a native requirement" row under _Gaps closed or aligned_ is incorrect (2026-07-27 correction).** Native `PiScanner.swift` scans `<project>/.pi/{skills,agents,prompts}` at scope `.project` and `<project>/.agents` at scope `.legacyProject` (PiScanner.swift:28–66, 406); `AppRefreshService.swift` watches those dirs per project. The electron refactor dropped them to global-only and encoded it in resource tests — a **regression**, not alignment. **Display parity is restored** for `<project>/.pi/{skills,agents,prompts}` (scan + watch, project shadows global, scope `project`). **Project skill writes are also restored:** P3 is done, so project skill create/edit/delete/rename/local-import mutations go through `EngineSkillStore`, and project skills materialized at `<project>/.agents/skills` are scanned back into the app. Project agent/prompt writes, native `<project>/.agents` legacy-project agent discovery, project agent assignments/defaults, and project MCP assignments remain open.
- **Shared skill-engine status is P3 done / P4 partial.** The engine owns in-app skill create/edit/delete/rename/local-import writes, including project scope; the dead `NativeSkillStore` is gone. The existing `collection-v1` Git import/sync and recovery path has not moved to the engine because its 0.1.4 conflict API cannot yet preserve Agent Deck's per-file choices and staleness guard. SKL-15/16 therefore remain open.

## Loops

Evidence corrections: the native repository contains no bundled Loop definitions, so Electron's empty initial Loop bank is not a functional difference (former LOOP-18). Native restart recovery marks active runs interrupted and retains their durable session/transcript, artifacts, worktree evidence, and checkout-recovery state; it does not rediscover arbitrary untracked operating-system processes. Electron now follows that same boundary (former LOOP-21). Explicit Discard closes the review lifecycle by atomically archiving the proven worktree inside Agent Deck's private root and pruning its Git registration; it deliberately retains the branch, artifacts, and quarantined files instead of using race-prone recursive deletion.

There are no active Loop-domain functional parity rows.

## Platform-specific exclusions and portable targets

These native implementations are excluded from required cross-platform parity:

- Apple Foundation Models and Apple Intelligence execution.
- Image Playground avatar **generation**.
- macOS Computer Use implementations and Apple-specific brokers.
- Xcode bridge specifics and Xcode-only MCP integration.
- AppKit/SwiftUI implementation details.
- Apple Dictation implementation.

Portable outcomes remain targets:

- Importing a normal avatar image file, storing it safely, and displaying it.
- Signed application updates and safe runtime updates.
- Notifications and badges that cover all sessions and route to the correct session.
- Platform-appropriate browser, terminal, editor, project discovery, and MCP behavior.

A platform-specific implementation difference is not a gap unless the portable user outcome, persistence, or safety property is missing.

## Ordered workstreams and dependencies

1. **Preserve dedicated Loop engine honesty.** Keep every structure on its typed Maker+Checker, Agent Pipeline, Parallel Agents, Discovery/Triage, or Human Approval path, and retain server-side rejection of invalid configuration rather than introducing fallback.
2. **Write and sync safety.** Preserve the native no-follow resource, Loop mutation, and managed collection capability boundaries, including private snapshot containment for collection scanning, watching, and Pi injection. Keep collection-v1’s clean-tree fail-closed update rule and preserve legacy copied-import per-path three-way merge, durable rollback/recovery, and explicit conflict choices.
3. **Isolation safety.** Preserve held-root, identity-bound session-worktree allocation and deletion plus typed merge preflights/outcomes. Validate and complete retention-policy acceptance across Electron E2E, real Pi, the full suite, and fresh Windows/Linux runtime coverage.
4. **Durable orchestration substrate.** Define durable child, run, session, artifact, approval, continuation, and worktree records. Loops and direct subagents should share this ownership model.
5. **Loop artifact depth.** Preserve the completed retained-worktree review and explicit apply/discard decisions while extending the shared artifact lifecycle without collapsing the five dedicated orchestration paths.
6. **Session input and transcript fidelity.** Add versioned attachments and file/folder/paste history, then per-message fork/rerun/edit and provenance.
7. **Attention and runtime state.** Persist failure/error/attention state per session, observe all sessions, count distinct sessions, route notification clicks, and add idle parking with deterministic teardown.
8. **Subagent/control-plane completion.** Add the remaining parent list/answer supervisor tools, continuation, reads, worktrees, artifacts, concurrency controls, direct launch, and missing agent config fields.
9. **Catalog and assignment depth.** Add multiple default/project agent assignment, MCP assignment, instruction assembly audit, extension/injected-command provenance, avatar file storage, and watcher coverage.
10. **MCP and issues.** Add HTTP create/edit, automatic OAuth callback, ownership/source controls, project config application, advanced fields, issue replies/reopen, and structured issue context.
11. **Memory calibration and transparency.** Match abstention gates, expose readiness/fallback, add recall cards/navigation, and add lifecycle controls before tuning lower-priority metadata.
12. **Tool depth.** Expand preview compatibility/inspection, diff scope, terminal organization, and checkpoint rerun semantics.
13. **Distribution.** Decide feeds, signing identities, rollout, and rollback. Implement app and Pi updates separately. Build and test Windows/Linux pipelines on those operating systems.
14. **Analytics decision.** Define consent, minimization, retention, offline behavior, and policy before treating analytics as implementation work.

## Recommended acceptance and validation

These are recommended checks for future implementation and regression coverage. They were not generally run for the original audit. LOOP-27 later passed the focused macOS arm64 validation described in the audit method. RES-01/02/03 and SKL-02 later passed the scoped cross-platform validation described there. The full E2E run still had unrelated existing failures and is not recorded as passing.

### Repository checks

- Run `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, and `pnpm test` for affected Electron slices.
- Run `pnpm test:pi` for Pi launch, sessions, streaming, subagents, Loops, MCP, memory, providers, resources, or extensions.
- Run `pnpm test:e2e` for renderer/backend and Electron behavior. Main/preload changes require the real Electron Playwright path and clean shutdown assertions.
- Run focused native build/XCTest checks when native runtime behavior is the acceptance oracle.

### Critical behavior checks

- Assert Maker+Checker, Agent Pipeline, Parallel Agents, Discovery/Triage, and Human Approval retain distinct capability, ordering, outcome, cancellation, recovery, and persistence behavior; invalid configuration must fail closed without fallback.
- Cancel or crash every Loop/subagent phase. Verify processes, process groups, waiters, bridge tokens, streams, artifacts, timers, and worktrees are cleaned exactly once.
- Verify streaming remains incremental and ordered under parallel children. Bound all queues and retained output.
- Test final symlinks, symlinked ancestors, junctions/reparse points, and validation-to-write races for every create/edit/rename/delete path.
- For collection-v1, modify tracked files and add untracked files, then update. Every dirty state must return `409` without pulling or changing the clone. For legacy copied imports, modify, add, rename, and delete non-`SKILL.md` files and verify no local change disappears without an explicit per-file choice.
- Put `SkillRepositories` or a persisted collection root behind symlinked ancestors. Clone, scan, watch, update, and delete must reject paths whose physical destination escapes the app-managed root.
- Force worktree creation failures. A session that requested isolation must not run in the primary checkout without explicit informed consent.
- Fork and rerun repeated identical messages. Verify the exact Pi entry and all original attachments are used once.
- Resume after restart and reconstruct images, files, folders, pastes, errors, attention, fork origin, plans, children, Loops, and artifacts from persisted records.
- Complete two background sessions and multiple events in one session. Badge count must equal distinct sessions awaiting review; notification click must select the source session.
- Test MCP OAuth state/PKCE, callback ownership, timeout, port cleanup, logout, token secrecy, source ownership, project assignment, and app quit.
- Calibrate memory with relevant, ambiguous, unrelated, embedding-unavailable, and secret-containing queries. Assert visible fallback and correct abstention.
- Validate release preflight for clean/dirty, ahead/behind/diverged, existing local/remote tag, push rejection, and rollback limits immediately before mutation.
- Validate the packaged macOS DMG and bundled Pi. Validate Windows/Linux packaging, native modules, PTY helpers, process-tree shutdown, signatures, and updates on those platforms when pipelines exist.
