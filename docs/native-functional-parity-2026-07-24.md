## Status and priority taxonomy

| Term           | Meaning                                                                                       |
| -------------- | --------------------------------------------------------------------------------------------- |
| **Present**    | Electron has the corresponding functional behavior.                                           |
| **Missing**    | Electron has no corresponding user behavior.                                                  |
| **Partial**    | A useful path exists, but a distinct behavior, state, or persistence path is absent.          |
| **Divergent**  | Both apps implement the area, but users get materially different behavior.                    |
| **Unsafe**     | The Electron path can violate a write, data, isolation, or release boundary.                  |
| **Unverified** | Source does not establish safe parity; focused validation is still required.                  |
| **Decision**   | Product/privacy policy must decide whether this should be ported.                             |
| **Equivalent** | The implementation differs, but the portable outcome is materially the same. It is not a gap. |

| Priority | Meaning                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------ |
| **P0**   | Release/parity blocker. No currently registered gap remains at this priority.                    |
| **P1**   | Data-loss/write-boundary risk, isolation/release safety issue, or missing load-bearing workflow. |
| **P2**   | Material limitation with a narrower usable path or workaround.                                   |
| **P3**   | Lower-frequency depth, convenience, diagnostics, or a product decision.                          |

## Executive verdict

Electron has a real and broad cross-platform product. Core Pi sessions stream incrementally. Resource CRUD, provider login, worktrees, Git, memory, MCP, issue browsing, terminal, browser, preview, files, diffs, onboarding, notifications, and signed/notarized macOS packaging all have working source paths.

It is **not at full native functional parity**.

- **No remaining P0 Loop structure gap:** Maker+Checker, Agent Pipeline, report-only Parallel Agents, Discovery/Triage, and terminal Human Approval checkpoints now have native-flat authoring and dedicated orchestration. Human Approval records and resolves durable app-data checkpoints without allocating Pi, validation, checkout-lock, or worktree resources.
- **P1 safety posture:** legacy copied-skill updates now three-way merge the complete payload tree and require per-path choices for overlapping changes; there is no coarse whole-folder remote action. Their durable transaction/recovery path, resource catalog mutations, engine-backed Git collections and per-file stale-review guard, requested project-session worktree isolation, and release synchronization fail closed when their safety boundary cannot be established.
- **P1 workflow gaps:** transcript attachment fidelity remains incomplete outside the now-closed stable-entry fork/edit/rerun path. Generic child runs now have first-class durable records with restart recovery, parent-owned reopenable read-only transcripts, same-child continuation through opaque Pi resume handles, app-owned artifact evidence, caller-bounded parallel concurrency, and optional retained per-child worktree isolation for `managed_parallel`. They intentionally remain owned by the parent rather than becoming top-level sidebar chats. Loop run timelines, proven launch ownership, and validated retained-worktree review are present; apply/discard decisions are implemented and covered by focused server/E2E tests. Running-turn guidance/follow-up input is present; arbitrary crash-orphan process discovery remains unavailable.
- **Distribution is only partly cross-platform:** the macOS DMG and bundled Pi are real. App updates, independent Pi updates, and Windows/Linux release/sign/update pipelines remain absent.

The honest release sequence is: close the remaining data and release hazards, extend durable orchestration/session records, then complete portable update and catalog depth.

### SUB-08 — parent-owned child transcript inspection

Every generic child card now opens a parent-owned read-only transcript while running and after completion, failure, stop, interruption, continuation, or restart. Live cells project from the existing single Pi event consumer; terminal and restart reads reconstruct pinned Pi `get_entries` active ancestry. The UUID-scoped parent/run endpoint returns sanitized cells only, rejects foreign pairing, revalidates owned evidence before and after asynchronous reconstruction, and labels retained legacy/external evidence `summary_only`. Parent deletion invalidates live reads and remains the only cleanup transaction.

Acceptance passed `pnpm typecheck`, lint/design-system/format, the full workspace suite (server 602, web 197), all 82 pinned real-Pi tests, and the focused SUB-08 E2E scenario. The updated real-Pi test proves multiple ordered live child updates before finalization alongside ordered parent deltas (one consumer), then canonical user→assistant ancestry. ### SUB-11 — caller-bounded managed parallel concurrency

`managed_parallel` accepts optional integer `concurrency` from 1 through 8, defaults to 4, and caps the worker count at the task count. A bounded work-conserving pool starts each durable run, artifact root, and optional SUB-12 worktree only when its slot begins; settled output remains in input order with the existing mixed-failure semantics. Parent teardown rejects still-queued tasks in place without entering `runSubagent`.

Focused server coverage proves schema rejection before launch, default/requested/capped limits, deferred overlap, reverse completion with failure, ordered rendering, worktree forwarding, and teardown suppression. The pinned real-Pi scenario uses controlled provider gates for three worktree-isolated tasks at concurrency two, proving actual overlap never exceeds two, ordered incremental deltas/results, three distinct retained worktrees, and an unchanged parent checkout. Local acceptance recorded 651 passing server tests (3 skipped), all 75 pinned real-Pi tests, typecheck, lint/design-system, and format checks. Native addon rebuild was blocked because Cargo was unavailable; native code was unchanged and the existing macOS arm64 addon passed smoke before the real-Pi suite. This call-local runtime scheduling adds no persistence or sync seam and no renderer/Electron surface.

### SUB-12 — isolated worktrees for managed parallel children

`managed_parallel` now accepts top-level optional `worktree`; false/omitted preserves the parent cwd, while true requires a distinct app-owned detached Git worktree at the parent's proven repository/HEAD for every fresh child. Allocation and exact Git/repository proof complete before that child's Pi starts, with no checkout fallback. Durable v3 child records retain opaque native identity, parent-repository identity, immutable allocation-base commit, and internal path evidence across completion, failure, stop, and restart. Parent deletion stops children first, then re-proves native identity and exact detached Git registration, removes and prunes worktrees, and only then removes artifacts/records; unsafe cleanup remains retryable.

Local acceptance passed the native addon build/smoke, typecheck, lint/design-system/format checks, the full workspace suite (including 615 server tests), all 74 pinned real-Pi tests, and the web/backend builds. The real-Pi scenario proved two writer children used different retained worktrees, the parent checkout remained unchanged, multiple ordered deltas arrived for each child before finalization, restart preserved ownership evidence, and parent deletion removed both registrations/worktrees and durable records. Full E2E recorded 217 passed/14 skipped; three unrelated existing failures remained in Loop retry focus, installed Pi 0.83.0 versus the test's 0.82.0 expectation, and the terminal shortcut. The full bundled-runtime build was blocked by unavailable private-package credentials after native, web, and backend builds passed. Runtime acceptance was macOS arm64; portable path normalization, spaces, commit-then-delete, post-add crash recovery, allocation/deletion serialization, and parent-path replacement rejection were covered locally, while Windows junction/reparse and Linux runtime execution remain unrun in this slice. `SessionWorktreeStore` supplies held native identity for every app-owned child leaf, but its managed-root boundary cannot safely capture an arbitrary ambient parent repository. Parent replacement is therefore bounded by repeated canonical Git repository/commit proof immediately before `git worktree add`, then exact registration/repository/native-identity proof immediately before Pi spawn and deletion; a same-process ambient-parent swap remains a bounded filesystem race rather than being papered over with an unsafe generic inode token.

## Corrections to older parity claims

- Provider login is not OAuth-only. API-key and OAuth login, search, grouping, method choice, browser launch, re-authentication, and credential replacement are present. Only an explicit renderer logout/remove action is missing.
- macOS packaging is not parked. Electron has an electron-builder DMG path with hardened runtime, signing, notarization, and bundled pinned Pi.
- Notifications and badges are present. Their remaining gaps are all-session observation, distinct-session counting, durable state, and click routing.
- Basic named, caller-bounded parallel, streaming, same-child continuation, optional detached per-child parallel worktrees, app-owned child artifacts, and parent-owned reopenable/inspectable child transcripts work. Generic children remain deliberately subordinate to their parent rather than appearing as top-level sidebar sessions. The missing area is the richer parent tool catalog and configuration depth.
- **SUB-10 was not a valid single-child parity gap at native `13083be` and is removed (2026-07-31 correction).** Native `ManagedSubagentParams` and `PiManagedSubagentBridgeRequest` omit a worktree field, while `runManagedNativeSubagent` hard-codes `useWorktreeIsolation = false`. `PiNativeSubagentRunSheet` declares a worktree toggle but has no call site, so latent `PiSubagentWorktreeService` / `runSingle` infrastructure is not shipped user behavior. Loop's **New worktree** target is a separate Loop launch/review workflow, not single `managed_subagent` parity. SUB-12 is now closed: top-level `managed_parallel.worktree` allocates a distinct retained app-owned detached worktree per fresh child and fails closed before child Pi spawn.

## Platform-specific exclusions and portable targets

These native implementations are excluded from required cross-platform parity:

- Apple Foundation Models and Apple Intelligence execution.
- Image Playground avatar **generation**.
- macOS Computer Use implementations and Apple-specific brokers.
- Xcode bridge specifics and Xcode-only MCP integration.
- AppKit/SwiftUI implementation details.
- Apple Dictation implementation.

Portable outcomes remain targets:

- Importing a normal avatar image file, storing it safely, and displaying it.
- Signed application updates and safe runtime updates.
- Notifications and badges that cover all sessions and route to the correct session.
- Platform-appropriate browser, terminal, editor, project discovery, and MCP behavior.

A platform-specific implementation difference is not a gap unless the portable user outcome, persistence, or safety property is missing.

## Ordered workstreams and dependencies

1. **Preserve dedicated Loop engine honesty.** Keep every structure on its typed Maker+Checker, Agent Pipeline, Parallel Agents, Discovery/Triage, or Human Approval path, and retain server-side rejection of invalid configuration rather than introducing fallback.
2. **Write and sync safety.** Preserve the native no-follow resource and Loop mutation boundaries plus the engine-backed collection seam. Keep 0.1.5 per-file conflict choices, stale-review rejection/refresh, automatic non-overlap merging, exact-byte outcomes, and recovery behavior behind `EngineSkillStore`.
3. **Isolation safety.** Preserve held-root, identity-bound session-worktree allocation and deletion plus typed merge preflights/outcomes. Preserve the verified keep-after-merge policy and exact owned-branch cleanup on explicit session deletion; do not add an unsupported destructive age- or prefix-based scavenger.
4. **Durable orchestration substrate.** Preserve app-owned child artifact/session ownership, retained detached parallel-child worktrees, and parent-owned reopenable child transcripts while extending the durable generic run substrate with approval ownership. Keep Loop worktree ownership separate from generic parallel-child worktrees; Loops and direct subagents should otherwise converge on this ownership model.
5. **Loop artifact depth.** Preserve the completed retained-worktree review and explicit apply/discard decisions while extending the shared artifact lifecycle without collapsing the five dedicated orchestration paths.
6. **Session input and transcript fidelity.** Preserve completed stable-entry fork/edit/rerun provenance and add versioned attachment fidelity outside that path.
7. **Attention and runtime state.** Persist failure/error/attention state per session, observe all sessions, count distinct sessions, route notification clicks, and add idle parking with deterministic teardown.
8. **Subagent/control-plane completion.** Preserve stable-ID same-child continuation, app-owned artifacts, and fail-closed parallel-child worktree isolation while adding the remaining parent list/answer supervisor tools, reads, concurrency controls, direct launch, and missing agent config fields.
9. **Catalog and assignment depth.** Add multiple default/project agent assignment, default MCP assignment, instruction assembly audit, extension/injected-command provenance, avatar file storage, and watcher coverage.
10. **MCP and issues.** Add HTTP create/edit, automatic OAuth callback, ownership/source controls, broader config discovery, advanced fields, issue replies/reopen, and structured issue context.
11. **Memory calibration and transparency.** Match abstention gates, expose readiness/fallback, add recall cards/navigation, and add lifecycle controls before tuning lower-priority metadata.
12. **Tool depth.** Expand preview compatibility/inspection, diff scope, terminal organization, and checkpoint rerun semantics.
13. **Distribution.** Decide feeds, signing identities, rollout, and rollback. Implement app and Pi updates separately. Build and test Windows/Linux pipelines on those operating systems.
14. **Analytics decision.** Define consent, minimization, retention, offline behavior, and policy before treating analytics as implementation work.

## Recommended acceptance and validation

These are recommended checks for future implementation and regression coverage. They were not generally run for the original audit. LOOP-27 later passed the focused macOS arm64 validation described in the audit method. RES-01/02/03 and SKL-02 later passed the scoped cross-platform validation described there. The full E2E run still had unrelated existing failures and is not recorded as passing.

### Repository checks

- Run `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, and `pnpm test` for affected Electron slices.
- Run `pnpm test:pi` for Pi launch, sessions, streaming, subagents, Loops, MCP, memory, providers, resources, or extensions.
- Run `pnpm test:e2e` for renderer/backend and Electron behavior. Main/preload changes require the real Electron Playwright path and clean shutdown assertions.
- Run focused native build/XCTest checks when native runtime behavior is the acceptance oracle.

### Critical behavior checks

- Assert Maker+Checker, Agent Pipeline, Parallel Agents, Discovery/Triage, and Human Approval retain distinct capability, ordering, outcome, cancellation, recovery, and persistence behavior; invalid configuration must fail closed without fallback.
- Cancel or crash every Loop/subagent phase. Verify processes, process groups, waiters, bridge tokens, streams, artifacts, timers, and worktrees are cleaned exactly once.
- Verify streaming remains incremental and ordered under parallel children. Bound all queues and retained output.
- Test final symlinks, symlinked ancestors, junctions/reparse points, and validation-to-write races for every create/edit/rename/delete path.
- For engine-backed collections, create multiple overlapping file changes plus a non-overlapping upstream change. Verify detail paths, reject a formerly valid stale merge ID with `409`, refresh to a new ID, apply mixed Keep Mine/Take Remote choices, and assert exact selected and automatically merged bytes. Retain compatibility coverage for pre-0.1.5/base-less imports.
- Put `SkillRepositories` or a persisted collection root behind symlinked ancestors. Clone, scan, watch, update, and delete must reject paths whose physical destination escapes the app-managed root.
- Force worktree creation failures. A session that requested isolation must not run in the primary checkout without explicit informed consent.
- Fork and rerun repeated identical messages. Verify the exact Pi entry and all original attachments are used once.
- Resume after restart and reconstruct images, files, folders, pastes, errors, attention, fork origin, plans, children, Loops, and artifacts from persisted records.
- Complete two background sessions and multiple events in one session. Badge count must equal distinct sessions awaiting review; notification click must select the source session.
- Test MCP OAuth state/PKCE, callback ownership, timeout, port cleanup, logout, token secrecy, source ownership, project assignment, and app quit.
- Calibrate memory with relevant, ambiguous, unrelated, embedding-unavailable, and secret-containing queries. Assert visible fallback and correct abstention.
- Validate release preflight for clean/dirty, ahead/behind/diverged, existing local/remote tag, push rejection, and rollback limits immediately before mutation.
- Validate the packaged macOS DMG and bundled Pi. Validate Windows/Linux packaging, native modules, PTY helpers, process-tree shutdown, signatures, and updates on those platforms when pipelines exist.

- This is primarily a source review of the original exact Electron baseline `e2b64fa`, supplemented by the later focused LOOP-27 and SKL-15/16 macOS arm64, cross-platform RES-01/02/03 and SKL-02, and GIT-09 Windows/Linux/macOS validation described above; it is not a release qualification run.
