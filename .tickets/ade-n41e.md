# SRV-11: per-user Pi credentials on a shared server (own agent dir per Access identity)

Goal: on the shared server each signed-in user connects their own model providers (OAuth subscription sign-ins and API keys) and their sessions run on those credentials, never on the operator credentials. Facts that fix the design: Pi reads credentials from <agentDir>/auth.json where agentDir = $PI_CODING_AGENT_DIR or ~/.pi/agent (pi-coding-agent dist/config.js getAgentDir); a stored credential wins over a provider env var, and env vars are consulted only when no stored key exists (pi-ai dist/compat.js withEnvApiKey), so per-user env keys cannot override the shared OAuth sign-in and cannot carry OAuth at all; Pi 1.2 still has no auth-path override (checked 2026-10-14), so one agent dir per user is the only route. Agent Deck already resolves every Pi file through piAgentHome(roots) in packages/resources/src/paths.ts, and injects owner-specific env at the single spawn chokepoint in SessionManager.launch (gitIdentityEnv, ade-fr91). Design: (1) ResourceRoots gains optional agentDir; piAgentHome returns roots.agentDir when set, else home/.pi/agent (one-line change, every caller keeps working). (2) New apps/server/src/userAgentDirs.ts (same shape as gitIdentity.ts): userAgentDir(dataDir, user) = <dataDir>/users/<first 16 hex of sha256(lowercased email)>/agent; ensureUserAgentDir(sharedAgentDir, userDir) creates the dir 0700 and auth.json "{}" 0600 when missing, then symlinks every entry of the shared agent dir (directories and files alike: agents, agent-library, extensions, skills, prompts, themes, loops, bin, npm, sessions, settings.json, models.json, models-store.json, mcp.json, claude-bridge.json, keybindings.json, .env, and anything added later) except auth.json, skipping links that already point correctly and replacing dangling ones; idempotent, cheap, called before every spawn and every provider operation. The developer must check in the Pi 0.82 dist which agent-dir files Pi rewrites with a temp-file plus rename (that would turn a symlink into a private copy) versus writeFileSync (follows the link): settings-manager.js, package-manager.js, trust-manager.js, session-manager.js, agent-session.js; files written by rename are copied once instead of linked and the divergence is documented. (3) SessionManager.launch adds PI_CODING_AGENT_DIR=<owner dir> to the spawn env when meta.createdBy is set and the collaborator is configured (shared server only, wired in server.ts exactly like gitIdentities); sessions without createdBy keep the shared dir; resume after a server restart goes through launch so it keeps the dir. (4) Provider routes in apps/server/src/routes/settings.ts (GET /runtime/providers, POST login, POST logout) use providerRootsFor(request): rootsFor() plus agentDir = the requesting user dir when sharedServer and requestUser(request.raw) is set; the SRV-10 (ade-4lga) 409 on login/logout is removed; the env credential-key refusal from SRV-10 stays. (5) Web: ProvidersScreen when store.me is set re-enables the controls and shows the notice "These sign-ins are yours only and apply to the sessions you create on this server"; the sidebar or a composer error for a session whose owner has no credential for the selected provider is what Pi already reports (No API key found for ...), no new UI. (6) Security, state it in code comments and docs: this is per-user credential STORAGE and billing separation, not isolation; every Pi process runs as the same Unix user, so another user agent can read your auth.json or /proc environ (ADR 0003). No credential value is ever returned by an API (listProviders exposes status only, verify) or logged. Ops migration documented in docs/remote-server-poc.md: the operator moves ~/.pi/agent/auth.json into their own user dir (path printed by a small operator note, not a route) and leaves "{}" in the shared file so no session silently runs on the operator subscription; legacy sessions without createdBy and Doctor (packages/pi-host/src/doctor.ts hard-codes ~/.pi/agent/auth.json) still see the shared file and say so. Out of scope: Loops and subagent runs inherit the parent spawn env, nothing extra; per-user models.json or settings; Doctor per user.

## Design

GUARDRAILS (checkout mirrored live to the VM by Syncthing and it is the server working tree): never git checkout/switch/stash/reset here; never run git on the VM replica; deploy only via ssh dev then pnpm build:web and systemctl --user restart agent-deck-server; no pnpm build or full suites (low memory): run only the test files you touch, one at a time, plus eslint, prettier and the server tsc on changed packages; do not commit. Depends on SRV-10 (ade-4lga) for the shared refusal constant and the env key refusal. Keep user dirs under the server data dir (pathContainment helpers exist) and hash the email so the path carries no identity. Pattern precedents: gitIdentity.ts and its wiring in server.ts and SessionManager.ts (ade-fr91); sharedServer threading (ade-rpkm).

## Acceptance Criteria

Unit tests userAgentDirs.test.ts: stable hashed path, dir 0700 and auth.json 0600 created once, every shared entry except auth.json symlinked, dangling link repaired, second call is a no-op. sessionManager.test.ts: spawn env has PI_CODING_AGENT_DIR pointing at the owner dir when createdBy is set and the map is configured, absent otherwise. Route test: with sharedServer true and two different identities, GET /runtime/providers and POST login use two different auth paths (inject the login function and assert the authPath), logout on user A does not touch user B file; with sharedServer false the shared path is used and no users dir is created. Web test: ProvidersScreen with me set shows the notice and enabled controls. docs/remote-server-poc.md: new Credentials section (per-user dir layout, migration step, trust statement, legacy and Doctor limits) and the Known gaps entry from SRV-10 updated. Live check by the architect after deploy: a session created by the owner on the VM has PI_CODING_AGENT_DIR in /proc/<pid>/environ and /runtime/providers through the tunnel lists the owner sign-in from the user dir.
